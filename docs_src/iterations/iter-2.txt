--------------------------------------------------------------------------------
1. OBJECTIVE & EXPERIENCE OVERVIEW
--------------------------------------------------------------------------------
Provide an engaging, deterministic, interactive 3D robotics showcase for web 
visitors of the deployed simulation. 

The workspace starts EMPTY with the UR5e in a static IDLE home pose. 
Depending on the branch the code base have TWO mutually exclusive operational flows:
  Flow A: Click-to-Place (Raycast Dispatch) + Defect QC Inspection
  Flow B: Conveyor Belt Feed (Dynamic Tracking) + Defect QC Inspection

Each flow sorts gearwheels across 4 physical destinations:
  1. White Spindle Tower   (Good White Gears)
  2. Green Spindle Tower (Good Green Gears)
  3. Blue Spindle Tower  (Good Blue Gears)
  4. Scrap Chute / Bin   (Defective / Cracked Gears of any color)

--------------------------------------------------------------------------------
2. SYSTEM CONSTRAINTS & PERFORMANCE GUARANTEES
--------------------------------------------------------------------------------
- Mutual Exclusion: Exactly ONE flow seats in each dedicated branch.
- Bounded Capacity: Each spindle tower holds max 10 gears (Flow A: FIFO eviction;
  Flow B: tower auto-empties at 10 with a short fade). Scrap bin empties at 100.
  Flow B belt holds at most BeltCapacity (~10) gears at a time. This guarantees:
    * Zero frame drops or WebGL draw-call saturation on low-end hardware.
    * Deterministic physics simulation without heap memory leaks or pile-ups.
- Busy-State Gating (Resource Saver): UI disables "Add Gear" / raycast placement 
  whenever robot_state != IDLE (e.g. EXECUTING). Prevents queue congestion, 
  race conditions, and unneeded physics objects while robot is active.
- Grasping Seam: Use threshold link attachment (parenting to `tool0`) when the 
  end-effector reaches within 15mm of gear center, avoiding unstable contact-friction 
  jitter in browser/VM.

--------------------------------------------------------------------------------
3. DETAILED FLOW SPECIFICATIONS
--------------------------------------------------------------------------------

[FLOW A: CLICK-TO-PLACE + DEFECT QC]
1. User clicks the "Mode: Click-to-Place" toggle in the TeleopClient UI.
2. User hovers and clicks on the 3D table plane inside the Three.js viewport:
   - Three.js Raycaster computes intersection coordinates (x, y) on table mesh.
   - Boundary Check: If (x, y) is within UR5e reach radius (0.35m <= R <= 0.75m), 
     a valid landing target indicator renders green; if out of reach, renders red.
3. On valid click, UI sends `RobotCommand`:
   {
     "type": "SPAWN_OBJECT",
     "payload": {
       "mode": "RAYCAST",
       "x": x_table,
       "y": y_table,
       "color": "random(WHITE, GREEN, BLUE)",
       "defective": "boolean (20% probability)"
     }
   }
4. Mesh drops onto table at (x, y). If defective, mesh includes visible crack notch.
5. UR5e executes vision inspection (camera above table), classifies color and defect:
   - If DEFECTIVE: MoveIt2 routes arm to pick and discard gear into the Scrap Bin.
   - If GOOD: MoveIt2 routes arm to pick and stack gear onto matching color spindle.
6. Arm returns to Home/IDLE pose awaiting next click.

[FLOW B: CONVEYOR BELT FEED + DEFECT QC]  (branch feat/conveyor-flow; details: specs/unit8/)
Layout: the conveyor replaces the table in front of the arm, running along Y (+Y -> -Y).
        A FeedHopper sits at the upstream end (robot left), the Scrap Bin under the belt exit
        (camera side). Spindle towers stand on a rear stand behind the arm (-X).
1. User clicks "Fill" (Process disabled). The hopper fills with a deck of 100 gearwheels:
   exactly 10 defective (random color) + 30 White / 30 Green / 30 Blue intact, shuffled.
2. User clicks "Process" (Fill disabled). The belt starts and gears drop from the hopper one
   by one with a random delay at a random position across the belt. Each belt run carries a
   random batch of 3..BeltCapacity gears (the last batch may be smaller).
3. The belt stops when the lead gear of the batch reaches the far edge of the PickZone.
4. The UI registers gears one by one with the workcell (coordinates + color + intact):
   - Intact gear: the arm picks it and stacks it on its color tower; the UI waits for IDLE.
   - Defective gear: the workcell books it into the Scrap Bin at once, the arm does not move;
     the gear stays on the belt and falls into the bin when the belt next runs.
5. When the batch is done the arm returns HOME and the belt restarts, repeating until the
   hopper is empty. A final flush run drops the remaining defective gears into the bin,
   then the belt stops, the arm idles, Fill is enabled and Process disabled.
6. "Stop" freezes the belt and stops new picks (the current pick finishes); "Process" resumes.
   Emergency Stop -> FAULT -> full reset. A page reload / reconnect is also a full reset.
7. Towers auto-empty (fade out) when they reach 10. The Scrap Bin is binary: green when
   empty, red when it holds anything; it empties at 100.
8. No scanner in this iteration: gear color and defect are known when they enter the belt.

4. TELEMETRY & OBSERVABILITY INTEGRATION
--------------------------------------------------------------------------------
The TelemetryMonitor sidebar updates in real-time during both flows:
- `robot_state`: IDLE -> EXECUTING (PICKING/PLACING) -> IDLE.
- `inference_metrics`:
    {
      "latency_ms": 12.4,
      "confidence": 0.98,
      "detected_object": "gear_green_good" | "gear_white_defective"
    }
- Tower Counters:
    [ White: 2/10 ] [ Green: 1/10 ] [ Blue: 10/10 (FULL) ] [ Scrap: empty | not empty ]

--------------------------------------------------------------------------------
5. POTENTIAL GAPS & DESIGN DECISIONS TO RESOLVE BEFORE IMPLEMENTATION
--------------------------------------------------------------------------------
1. Workspace Reset / Clear:
   - Need a "Reset Workspace" / "Empty Bins" button in UI to reset towers back 
     to 0 when all 9 gears are sorted.
2. Reachability Clamping:
   - In Click-to-Place, clamp or reject clicks too close to base singularity 
     (R < 0.25m) or outside joint reach (R > 0.80m).
3. End-Effector Graphic:
   - Mount a clean pneumatic suction cup or two-finger gripper model to `tool0` 
     to make the pick animation visually legible.
