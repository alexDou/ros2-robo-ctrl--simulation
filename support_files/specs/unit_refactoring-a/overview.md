### Production ROS2 Native Architecture & Real-Hardware Refactoring (Unit Refactoring-A)

* **Goal**: Refactor the simulation prototype backend into a production-grade, real-hardware-ready ROS2 native architecture per [ADR 0004](../../docs/adr/0004-real-robot-ros2-native-architecture-and-gateway-throttling.md) and [unit_6_5_refactoring_architecture.md](../unit_6_5_refactoring_architecture.md). Replace simulation shortcuts with standard ROS2 Jazzy architecture: upstream `ros2_control` + `ur_robot_driver` (500 Hz RTDE loop with `use_fake_hardware:=true/false` switch), decouple monolithic `EdgeNode` into standalone ROS2 nodes (`workcell_node` and `arm_controller_node`), define native ROS2 action and service interfaces in `robot_control_interfaces`, use upstream `zenoh-bridge-ros2dds` (installed via `cargo install`) managed by the Gateway launcher, and implement a high-throughput `TelemetryThrottler` in Rust Gateway decimating 500 Hz RTDE telemetry to 30 Hz for WebSocket delivery while forwarding Action feedback.
* **Architecture**: Contract-first staged development across decoupled ROS2 packages in `src/ros2/` and Rust Gateway:
  * **Stage 0 (Refactor-A.0)**: `src/ros2/robot_control_interfaces` (`PickAndPlace.action`, `GetDropSlot.srv`, `ClearWorkspace.srv`).
  * **Stage 1 (Refactor-A.1)**: `src/ros2/workcell_manager` (`workcell_node.py` implementing inventory state, services, and `/workcell/inventory` topic).
  * **Stage 2 (Refactor-A.2)**: `src/ros2/arm_controller` (`arm_controller_node.py` wrapping closed-form analytical IK solver, `PickAndPlace.action` server, and trajectory dispatcher to `scaled_joint_trajectory_controller`).
  * **Stage 3 (Refactor-A.3)**: `src/ros2/robot_bringup` (`robot_nodes.launch.py` with `use_fake_hardware` switch).
  * **Stage 4 (Refactor-A.4)**: Edge Gateway `TelemetryThrottler` (500 Hz to 30 Hz) + Action feedback bridge + `scripts/launch_gateway.sh`.
  * **Stage 5 (Refactor-A.5)**: Multi-service system integration verification & legacy `src/edge_node/` retirement.
* **TDD Assertion Matrix**:
  * **Test 1 (ROS2 Interfaces / Colcon & Python)**: Build verification asserting `colcon build --packages-select robot_control_interfaces` compiles interfaces, generating valid C++ and Python message, service, and action types.
  * **Test 2 (WorkcellNode / Pytest & ROS2 CLI)**: Unit tests asserting `workcell_node` calculates next vacant SpindleTower slot ($z_k = (k \pmod{10}) \times 0.02\text{m}$), handles `GetDropSlot.srv` requests, resets inventory on `ClearWorkspace.srv`, and emits `/workcell/inventory`.
  * **Test 3 (ArmControllerNode / Pytest & Action Client Harness)**: Unit tests asserting `arm_controller_node` action server receives `PickAndPlace.action` goals, computes analytical IK waypoints in <0.2ms, dispatches 10-step trajectory to `scaled_joint_trajectory_controller`, streams phase feedback (`APPROACHING` through `HOMING`), and halts motion on goal cancel.
  * **Test 4 (Robot Bringup / Launch Test)**: Launch test asserting `ros2 launch robot_bringup robot_nodes.launch.py use_fake_hardware:=true` successfully spins up `controller_manager`, `joint_state_broadcaster` (500 Hz), `scaled_joint_trajectory_controller`, `workcell_node`, and `arm_controller_node` with zero crashes.
  * **Test 5 (Gateway Throttler / Cargo Nextest)**: Unit tests asserting Rust Gateway `TelemetryThrottler` ingests 500 Hz joint states from Zenoh, downsamples via latest-sample non-blocking buffer to 30 Hz for WebSocket broadcast, forwards `PickAndPlace.action` goal requests, and relays Action feedback frames without latency creep.
  * **Test 6 (Integration / Playwright & Launchers)**: Multi-service end-to-end integration test asserting `robot_bringup`, `launch_gateway.sh`, and `launch_teleop-client.sh` run concurrently, table click dispatches target $\to$ Gateway translates to Action goal $\to$ arm executes 10-step motion $\to$ gear attaches and stacks on tower $\to$ 30 Hz telemetry renders with $<50\text{ms}$ latency budget.
