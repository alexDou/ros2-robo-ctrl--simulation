# Pull Request Toolkit Playbook

## 1. Tooling Prerequisites
* **GitHub CLI (`gh`):** Use `gh` for all GitHub interactions (`gh pr create`, `gh pr diff`, `gh pr comment`).
* **Rust SemVer Guard:** Use `cargo-semver-checks` to verify public API stability if crate versions are unchanged.

## 2. Pre-Flight Gate (Must Pass Before PR Creation)
Never open or approve a PR if any step fails:
1. **Dirty Tree Check:** `git status --porcelain` must be clean.
2. **Rust Test & Lint Pass:**
   ```bash
   cargo clippy --workspace --all-targets -- -D warnings
   cargo nextest run --workspace --all-targets
   ```
3. **Web Frontend Pass:**
   ```bash
   npm --prefix web run typecheck
   npm --prefix web run test
   ```
4. **ROS2 Interface Breaking Change Check:**
   Verify if any `.msg`, `.srv`, or `.action` files were modified. Modifying existing field IDs or types without a major version bump is forbidden.

## 3. Pull Request Body Standard
Every PR generated by the agent must adhere to this Markdown structure:

```markdown
## Summary
- Concise bullet points summarizing the core changes and why they were made.

## Architectural Changes & Invariants
- **ROS2/Gazebo:** (Changes to topics, QoS, URDF, frames, or physics parameters)
- **Rust/Web:** (Performance implications, API updates, or coordinate sync changes)

## Breaking Changes & SemVer
- [ ] Yes (Describe breaking API changes or message definition modifications)
- [ ] No (Backward-compatible change)

## Validation Performed
- [x] Unit/Integration tests: `cargo nextest run` passed
- [x] Static analysis: `cargo clippy` and `npm run typecheck` passed
- [x] Visual validation: Simulation verified via Three.js visualizer
```

## 4. Review Evaluation Criteria (For Reviewing External PRs)
When auditing incoming PRs:
* **Blast Radius:** Trace every modified ROS topic and verify subscriber/publisher count.
* **QoS Alignment:** Confirm publisher and subscriber QoS policies match (`Reliable` vs `BestEffort`, transient local vs volatile).
* **Memory Invariants:** Check that no high-frequency loops allocate on the heap or leak listeners.
